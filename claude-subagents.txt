[0:30–1:05] DEFINITION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"A subagent is a specialized AI assistant that handles one 
specific type of task. It runs in its own separate context window, 
with its own instructions, and its own set of tools.

Think of it like sending an intern to go dig through the archives. 
You don't want every file they flip through cluttering your desk — 
you just want the answer they bring back. That's exactly what a 
subagent does."

On-screen: main conversation → subagent branches off → 
returns summary only

"You might be thinking — can't I just ask Claude to do the 
research right in my conversation? You can, but every file it 
reads and every search it runs stays in your context, filling it 
up fast. A subagent keeps all that work separate."

[1:25–2:00] WHY IT MATTERS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"Without subagents, long sessions get noisy. Your context fills 
with logs, file contents, and search results you'll never look at 
again. Responses get slower, vaguer, and Claude starts losing 
track of what's important.

With subagents, the noisy work happens somewhere else. You keep a 
clean, focused conversation — and you can even hand different 
subagents different tools, so a research subagent can't 
accidentally edit files."

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"A few examples: 
  • A subagent that only reviews code and can't touch it
  • A subagent that runs your test suite and reports failures
  • A subagent that researches your codebase's authentication"

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[2:55–3:30] THE SUBAGENT FILE, SIMPLIFIED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"Every subagent is just a small markdown file with two parts. 

First, a short description at the top that tells Claude 'what this 
does' and 'when to use it.' Claude always keeps this in mind when 
deciding whether to delegate.

Second, the actual instructions — the subagent's own system 
prompt, plus which tools it's allowed to touch. Claude only hands 
off to that subagent when the task actually matches, so it's not 
spinning up unnecessary work."

On-screen visual: Two-layer diagram
  "Description [always visible]" 
  → "Instructions + tools [used only when delegated]"

code, or one scoped to your own database rules — just describe it 
to Claude in plain language.

Tell Claude something like: 'Create a personal code-improver 
subagent that scans files and suggests improvements, and make it 
read-only.' Claude writes the whole file for you — the 
description, the instructions, everything."

be used, and which tools it actually needs. Instead of 'helps with 
code,' say 'use this after code changes, and only give it read 
access.'"

"So — a subagent is a focused assistant you set up once, Claude 
automatically knows when to hand off to it, and you can either 
lean on the built-in ones like Explore and Plan, or describe a 
custom one and let Claude write it. Either way, you get a cleaner 
conversation and smarter context management. That's it."
